# 运营报表整理与交付

使用已安装的 `report-delivery` CLI。若入口不存在，先定位包含 `pyproject.toml` 的本项目并安装；不要从零重写处理逻辑。安装方法和输入规范在仓库 README.md 中。不需要 skill 也能直接运行脚本。

## 先选择用途

- 演示或求职展示：运行 `report-delivery demo --out <空目录>`。只有模拟数据及本地副本，不能描述为真实 NAS 上传。
- 处理真实文件：明确原始文件、统计范围与输出目录，然后 `report-delivery process <原始xlsx> --start YYYY-MM-DD --end YYYY-MM-DD --out <独立目录>`。
- 范围未指定时可运行 `report-delivery plan` 取得北京时间昨天所在月份 1 日至昨天的范围；须确保输入报表确实对应这个范围，不借用旧文件冒充新数据。

## 固定规则

输出九列依次为视频ID、视频发布时间、抖音号ID、发布次数、累计播放次数、累计直接成交金额、累计直接成交券数、累计直接核销金额、累计直接核销券数。发布次数每行数值 1。保留原始业务行和顺序，不去重、不二次删除全零行。原始文件保留备份，不能通过改源值让核验通过。

不得自行改变列宽、默认行高、字体和 General 格式。输入必须具备统计日期、视频标题及输出所需字段；无法确认后台筛选口径时说明限制。脚本失败时读取具体结果，不改状态为成功。

## 核验和交付

1. 运行 `report-delivery verify <目录/manifest.json>`，确认完整核验通过。
2. 已有同一目标的上传授权时继续；没有明确目标目录或覆盖授权时先确认范围。
3. 用 `report-delivery upload <manifest> --config <本地配置>` 预览。该命令默认不联网。
4. 确需实际发送时加 `--execute`。凭据用交互输入或秘密注入环境变量，不写进命令参数、聊天、配置或日志。
5. 仅 `uploaded` 表示 API 返回成功且路径、大小、新修改时间经回读确认。远端哈希没有核验，不声称一致。`planned`、`verified`、`demo_completed` 均不表示真实上传成功。

演示记录不能上传；结果不确定的尝试、残留锁、被修改的文件都需要检查后恢复，不清理记录后盲目重传。不关闭 TLS 校验绕过连接错误。

最后只报告真实状态、日期范围、行数、产物位置或具体阻碍。不要泛化为连续多日稳定无人值守。
