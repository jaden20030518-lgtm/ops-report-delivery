# 设计与取舍

## 为什么从报表文件开始

原始实践把网页操作、本地处理和公司盘交付串在一起。网页选择器、登录态、平台排队、公司网络分别可能失败。公开项目聚焦“已有导出 → 整理 → 核验 → 交付”，让读者能在没有私有账号的情况下重现核心规则。浏览器采集、Cookie 读取、系统钥匙串和日程调度不包含在本仓库中。

公开版使用 Python 和 openpyxl 重建已确认的样式规则，不依赖特定桌面应用捆绑的运行时或私有表格工具。这里保证的是列宽、行高、字体、单元格格式和内容规则，不承诺与某个私有模板的 XML 字节完全相同。

## 转换不等于核验

处理前检查输入的必需字段、统计周期、发布时间、标识符精度和空表。处理后重新打开输入和输出，比较行数、行顺序、每个字段值和单元格类型，并检查样式。原始备份和整理版分别计算 SHA256。

全空行不是业务记录，会跳过；有视频记录但指标全为 0 的行会保留。重复视频 ID 不被当作脏数据自动删除。数字字符串的千分位分隔符会移除，数值经 Decimal 核验；无法被 Excel 数值精确保存并通过回读比较的数据会失败，不悄悄近似。

## 状态及恢复

- `processing`：备份、写入或核验尚未完成；不能上传。
- `failed`：本地处理失败，保留现场；修复原因后用新的运行目录，避免覆盖证据。
- `verified`：本地数据和格式已核验；真实数据可进入明确授权的上传。
- `planned`：一次本地交付预览结果，不改变执行记录、不访问网络。
- `uploaded`：发送成功且目标路径、大小、新修改时间已经回读确认。
- `demo_completed`：合成演示和本地副本校验完成，不代表网络上传。

同一运行目录复用必须满足输入哈希、日期和演示标记一致。上传完成记录同时绑定规范化的服务器地址和完整远端路径，切换 NAS 后不能沿用旧完成状态。上传中的 `upload-attempt.json` 在发出请求之前写入；请求结果不确定时保留记录并停止，不能由 Agent 猜测成功。远端内容没有做 SHA256 校验；状态证据仅限接口结果与元数据回读。

目录锁防止同一运行目录的并发操作。进程崩溃可能留下 `.run-lock`，此时停止并检查原进程。它不提供跨机器或跨运行目录的全局锁；使用者应确保同一目标只有一个调度者。不同目录或其他客户端仍可能改写远端文件，这不是分布式“恰好一次”系统。

## 输入与信任边界

执行记录是本机操作证据，不是防恶意篡改的签名凭据。文件哈希可发现意外修改，但不防止同时篡改文件和记录的本地攻击者。真实上传需要操作者确认原报表来自正确筛选，并确认目标目录及覆盖范围。

凭据来自交互输入或秘密注入的环境变量，不写入记录。网络错误仅输出异常类别，避免将含会话参数的请求 URL 打进日志。HTTPS 校验保持开启，支持自定义 CA 文件；没有关闭校验的选项。
