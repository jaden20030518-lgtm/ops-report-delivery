# 面试时怎样讲这个项目

## 一分钟介绍

> 我在处理运营日报时，发现难点不只是把表下载下来，而是每次都要维持相同的数据口径和模板要求，还要确认公司盘里的文件真正更新了。我把流程拆成了数据整理、独立核验和交付三个部分：保留全部原始记录及顺序，固定输出九列；核验失败就不允许上传，上传结果不确定也不冒报成功。开发使用了 Codex 辅助，我主要负责提供和修正业务规则、用手工样表验收、反馈异常并推动迭代。公开项目使用模拟数据，别人不需要公司账号就能运行核心流程。

这是基于实际任务的表述范例，请按本人能解释、能演示的范围使用。

## 可以展示的个人贡献

1. 明确时间范围、账号范围、指标口径及月初处理规则，把口头步骤变成可检查的条件。
2. 用自己整理的样表检查字段和格式，纠正长 ID、列宽、行高、字体以及是否删除全零行的问题。
3. 识别逐屏 Agent 操作的时间成本，推动固定脚本执行，并保留 Agent 处理异常的职责。
4. 区分已下载、已核验和已上传，用执行记录和回读证据判断实际完成状态。

不要把 AI 辅助生成的代码全部描述成独立手写，也不要把团队业务成果归因于一个自动化脚本。

## 用演示回答追问

- “全零数据是不是应该删？”——运行 demo，看全零行保留；后台筛选与下载后二次删行是两个不同决定。
- “重复视频 ID 为什么不去重？”——示例刻意包含重复 ID，工具只执行已确认的逐行转换，不擅自改变数据粒度。
- “怎么证明没有改坏数据？”——展示独立回读比较、长 ID 字符串类型、格式检查和文件哈希；改一个指标或字体，测试会阻止通过。
- “上传报错会怎样？”——记录保持未完成，保留发送尝试，先检查远端；不会因超时就再次覆盖。
- “为什么不保证十分钟？”——脚本执行、平台排队和网络连接是不同耗时来源。没有完整测量前不承诺耗时或收益。

## 简历表述参考

> 基于运营日报场景，定义固定字段、日期及模板验收规则，借助 AI 编程工具实现报表整理、逐行核验和可配置交付；提供合成数据演示、异常处理与自动测试，并整理为可复用脚本及 Agent skill。
